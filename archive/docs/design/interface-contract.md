# V3 interface / acceptance contract

Frozen against candidate `d066411` after independent dataflow and allocator reviews; earlier mathematical thresholds remain withdrawn.

## Adjudication and smallest implementation

Both reports support single-request eager, no radix/prefix sharing, no speculation/overlap/PD, whole-prompt handoff. Choose **release actual raw tensor backing while retaining existing logical token allocator leases**, not a second page allocator. Returning pages to a free-list of an unchanged full tensor does not itself save backing; an additional physical allocator is unnecessary for this single active request. Original req_to_token and compressed index-K arithmetic stay unchanged for the entire request.

Use a narrow opt-in QSA V3 adapter attached to the QSA pool/backend. First eager decode metadata initialization is the handoff boundary: the previous final prefill forward has been enqueued, and no decode attention has run. Event-gated copies complete before raw storage is released. This is intentionally blocking at the boundary, not a new asynchronous scheduler staging queue; cancellation requested during handoff is processed after its bounded copy drain. The first sampled output belongs to prefill; report handoff latency separately from TTFT and include it in the first inter-token gap. This avoids inventing TP scheduler readiness or a new allocator framework in V3.

Modes: `SGLANG_QSA_HISPARSE_V3=resident|offload`, absent disables all hooks. Both measured modes require same source/argv: TP2, PP1, 1 KV head, head_dim256, FP8 E4M3/NHD, C4/page64, 12 full layers, max-running-requests1, no overlap, radix disabled, CUDA graphs disabled, no speculation or disaggregation. Context/logical pool capacity262144, chunk2048. Fail unsupported combinations before serving. First implementation requires prompts >=2048 tokens (512 complete C4 at decode); skip automatic server warmup. No silent resident fallback in offload mode.

Implementation freeze `ec24ba18bd`: both modes explicitly take the same existing FA2 branch. Validate the actual per-phase graph flags and the published resolved graph configuration; the legacy `disable_cuda_graph` field does not become true merely because both phases are disabled. Require one backend instance, ordinary independently owned MHA backing, no unified memory backing or streaming sessions. Request IDs must be unique within this bounded experiment; slot/rid identifies a lease, per-state generation rejects stale state, and the returned slot/rid/generation release token is committed only after logical/Mamba release. There is no externally scheduled callback registry. A failed partial handoff marks the adapter failed and propagates the error; it cannot resume resident serving.

Before GPU, require `--enable-deterministic-inference` identically in both modes, as the prior service comparison runner already required. The production argv does not contain this flag, so the candidate driver must add it explicitly; main adapter guard enforces it. This reduces a known confound for the exact greedy output-ID comparison and does not change the acceptance criterion.

## Data and lifecycle

- `begin_batch`: admit one request slot/generation on first prefill, record allocator/memory; prefill unchanged. First decode transfers prompt K/V (seq_len-1), using req_to_token for actual physical source order. Pinned host stores complete request-logical C4 records `[K0..3,V0..3]`; 0–3 pending raw tokens stay in a four-member GPU ring (physical rows1..4 plus reserved padding row0; see RING-CORRECTION-CONTRACT.md).
- Handoff copies bounded chunks, checks packed bytes against separately gathered original raw K/V, records producer→copy completion, and only then replaces raw layer backing with its five-row allocation (four tail members plus padding0). All raw pointer metadata is refreshed; index-K and Mamba backing remain unchanged. No logical token free occurs here. Record actual raw bytes and allocated/reserved high water, not just usage.
- Decode writes into the four-row tail through the **existing pool FP8 store/scale conversion** using remapped ring write locations1..4; slot0 is skipped by the existing writer. On the fourth member, pack into canonical newest hot C4, D2H to host behind producer event. Protect source until completion; subsequent H2D consumer waits on that completion.
- Raw selected indices are real QSA output. Recover 512 C4 indices, invoke existing HiSparse GPU resolver, gather, and use V4's indexed unpack into contiguous raw K/V (plus true pending tail). A separate compact req_to_token table maps the original selected raw indices to the compact buffers; the real global request table/index-K is never overwritten. Reuse the existing FA2 compact-extraction/descale and attention call, not an invented reference kernel.
- Normal finish/abort drains the adapter streams before common `release_kv_cache` frees logical/Mamba leases. Clear host/hot/request generation. Next real request lazily rebuilds the original raw backing before prefill, proving released storage is reusable. Stale generation/release calls fail rather than corrupt another request. No per-step global device synchronization; boundary and terminal event synchronization is allowed and reported.
- Mode resident observes the same lifecycle without changing storage. Shorter 2048-token sentinel requests are allowed to verify actual reuse, but cannot substitute for the main long request.

## Hard acceptance and minimal matrix

1. CPU: actual indexed packing/unpacking/mapping helpers including tail0/1/2/3, unsupported config guards, existing bounded supervisor check. Code review checks all last references and finish/abort path before GPU.
2. Same-source resident and offload services each run fixed request-A.json **261120 input IDs / 768 greedy outputs**, chunk2048. Every output token ID must match; 768 outputs contain 767 decode forwards. No tokenization changes or invented numeric tolerance. Each TP rank must log complete 12-layer handoff before its first decode, all 767 decode forwards, and release.
3. In offload mode, check handoff source bytes against original K/V before release and actual selected compact K/V against independently decoded host+tail at first/middle/last and C4/page boundaries; exact bytes are mandatory. Valid counts and scales follow existing source, immutable logical addressing stays alive.
4. Raw backing must shrink from the actual (capacity+padded page)*12*512 bytes to bounded ring/hot/scratch, with allocated/reserved measured separately. Index-K/Mamba storage retained. **Logical available count must not increase due to handoff.** This corrects the contrary suggestion in VALIDATION-PREP.md; only terminal release returns those slots. CUDA reserved/NVML may stay high. Real subsequent sentinel prefill reallocates the original raw backing in the same live process, then completes decode/release; process exit is not reuse evidence.
5. One real offload A cancellation request issued at the logged handoff boundary (or earliest decode if the handoff is too fast to intercept); record the actual phase, drain outstanding work through actual abort/release, then run a 2048-token sentinel. No synthetic success for an unobserved cancellation phase. If an acceptance obligation cannot be exercised, report its gap; do not expand the whole test matrix.
6. Record source commits, actual argv, per-rank generation/phase/seq, logical free counts, raw/index/host/hot/workspace bytes, CUDA allocated/reserved peaks, sampled NVML peak, copy bytes/event/wall and output IDs. No V3 latency gate invented: report handoff/TTFT/TPOT; V4's 2.427575ms is not a service TPOT threshold.

Highest possible result is `PASS_V3_SINGLE_REQUEST_EAGER`. Other results are specific FAIL/BLOCKED with evidence; no graph/prefix/concurrent-service qualification, no eight-request GO. V3 cannot reduce the resident prefill peak in this first implementation.

## Execution and preservation

After actual-code CPU checks and independent review, an executor may run one bounded GPU window under the existing idle/test-endpoint/finally-restore protocol. Preserve all historical attempts and failures; no upstream merge or deployment follows from this check. Long execution uses one completion notification, not repetitive model polling. Private environment values stay only in controller memory.
