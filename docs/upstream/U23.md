## 1. Frozen lifecycle contract

This is the fork's behavior (`ee8fe158d6`), the reference any upstream hook
placement or Phase 4 rewrite must preserve. Line numbers are `fork:` files
under `python/sglang/srt/`.

### Objects and owners

| Object | Allocator / owner | Identity |
| --- | --- | --- |
| Logical pages (compressed index under QSA) | paged `token_to_kv_pool_allocator`, mapped in the request's `req_to_token` row | page ids |
| Request row, Mamba/PLE slot | `req_to_token_pool` (`HybridReqToTokenPool`) | `req_pool_idx`, `req_generation[req_pool_idx]` |
| Physical lease (raw staging K/V, C4 ring) | runtime `QSAHiSparseSlots` (`mem_cache/qsa_hisparse/slots.py`) | `QSAHiSparseLease(req_pool_idx, generation, rid, slot)` |
| Host snapshot | `HostPrefixCache`; pinned by a `PrefixReader`, written through a `PrefixReservation` | entry id, `signature = (namespace, length, sha256(tokens))` |

Lease phases (`slots.py`): `prefill` -> `copying` -> `host_ready` ->
`decode` -> `releasing` -> `drained` -> `logical_flushed` -> committed
(slot back in `free_slots`); `failed` on a failed drain or handoff.

### Stages, in order, per request

**R. Restore** (host hit only; inside `alloc_for_extend`, `allocation.py`
344-477, M01).
- R1 After `alloc_req_slots` and before `prefix_tensors` is read:
  allocate `snapshot.length` fresh logical pages and make them the request's
  prefix (`prepare_prefix_for_extend`, `prefix_cache.py` 121). The match
  carried only a length (a `-1` marker).
- R2 After the suffix KV allocation: record the suffix pages
  (`note_extend_allocation`, 158) so rollback can free them; with the hook
  present `alloc_for_extend` does not free `out_cache_loc` itself on an
  `alloc_aux_to_lengths` failure.
- R3 After indices and kv lengths are written: acquire a fresh lease with
  the row's current generation and copy raw K/V into staging, the
  compressed index into the new pages, the pending ring, rope rows and
  recurrent/PLE state (`restore_prefix_for_extend` 167 ->
  `runtime.restore_prefix` 1141); then close the reader.
- R4 Any exception inside `alloc_for_extend` rolls back (wrapper 344-357,
  `rollback_prefix_for_extend` 189): drain the restore stream; free prefix
  and suffix pages, the Mamba slot and the row; `release` + `after_release`
  the lease if one exists; close the reader. A later chunk frees only
  suffix pages beyond its already-owned partial page and restores previous
  lengths. If rollback fails, the record is kept ("retained ownership") and
  blocks rematch, prepare and release.

**C. Checkpoint (capture)** (`_capture`, `prefix_cache.py` 267).
- Only in lease phase `prefill`, at `seq_len % 64 == 0`, for a request not
  barred from insertion.
- C1 After a non-final chunk or a non-finished final prefill: from
  `maybe_cache_unfinished_req` (`cache_unfinished_req` 314), before
  `admit_request_into_staging` (`batch_result_processor.py` 382-384).
- C2 At release of a request that finishes at prefill with insertion: from
  `before_release(req, is_insert)` (306), before the drain (stage D).
- C3 Capture reserves host bytes, waits for the producer stream, copies,
  converges TP, publishes, and closes the reservation in `finally`.
- C4 `before_release` raises if a restore record (R) is still open.

**A. Async copy (handoff)**. `admit_request_into_staging` ->
`runtime.handoff` (1424): phase `copying`, device-to-host copy on the copy
stream; `collect_ready_reqs` converges TP and moves the lease through
`host_ready` to `decode`.

**D. Drain** (`release_kv_cache`, `common.py` 275-276 ->
`runtime.release` 1666 -> `slots.drain` 111).
- D1 After C2 and before any of the request's pages or its row is given
  back (`cache_finished_req`, 279).
- D2 Records a terminal event on the producer stream and synchronizes it
  and every copy event of the lease (per-layer writebacks, handoff event);
  phase `drained`. Returns the lease, or `None` for an admitted request that
  never ran a forward.
- D3 On failure the phase becomes `failed` and the exception leaves
  `release_kv_cache` before anything is freed: ownership is retained.

**L. Logical release** (`common.py` 279-307).
- L1 Free the KV row (`cache_finished_req`), the over-allocated tail, the
  Mamba/PLE slot, then `req_to_token_pool.free(req)` and
  `mark_kv_released()`.
- L2 Then `runtime.after_release(lease)` (1697): inside a free group
  (`allocator.free_group is not None`) the lease is appended to
  `pending_releases` and stays `drained`; outside, it goes
  `logical_flushed` and is committed at once.

**F. Free-group flush** (`PagedTokenToKVPoolAllocator.free_group_end`,
`allocator/paged.py` 328-340, M02).
- F1 After the parked pages return to the allocator, `after_logical_flush`
  (1719) commits each queued lease in FIFO order
  (`logical_flushed` requires `free_group is None`).
- F2 A failed commit keeps the lease queued; a committed lease is never
  replayed.

**P. Physical reuse**. A committed slot returns to `free_slots` (sorted);
the next `acquire` (cold first chunk in `begin_batch`, or R3) takes it.
- P1 One prefill owns staging at a time; the scheduler admits at most one
  request, and none while staging is owned (S05, S06).
- P2 The generation for a `req_pool_idx` strictly increases across leases,
  including across `flush_cache` (M04, U9: monotonic `req_generation`).

### Invariants (what any reimplementation must keep)

1. C2 precedes D: a drain moves the lease out of `prefill`, after which
   capture is silently skipped.
2. C1 precedes A: the handoff moves the lease out of `prefill`.
3. D completes before any logical page or row of the request can be
   allocated again, and before the slot can be committed.
4. L2 runs after the row is freed; F1 commits only after the parked pages
   are back in the allocator. A slot is never reusable while its request's
   logical pages are parked.
5. On a failed drain (D3) or failed rollback (R4) nothing the request owns
   becomes allocatable.
6. TP: every rank reaches the convergence points (match, prepare, capture,
   staging collection) in the same order (prefix-cache.md section 3).

Invariants 3 and 5 are stated as the fork implements them: the drain runs
before the pages are given back, not merely before they are reused. Any
placement that drains later (see D below) needs an explicit equivalence
argument and orchestrator approval.

L2 placement. `release_kv_cache` ends with `req_to_token_pool.free(req)`
and `mark_kv_released()`, so a plugin `after` hook on
`sglang.srt.mem_cache.common.release_kv_cache` runs exactly at the fork's
point on the normal path. SGLang's `after` wrapper calls the hook only when
the original returns (`plugins/hook_registry.py` `_wrap_fn`, unchanged on
main), matching the fork, where an exception anywhere before the last
statement skips `after_release`. The two early returns (`not
req.kv.holds_kv`; `claim_kv_row` true) reach the hook as well, while the
fork never reaches its lease code there: the hook must act only on a lease
that the same call's pre-free drain (ask 1) recorded for that request, and
do nothing otherwise, which is also what the fork's `after_release(None)`
does. `on_release` is not used for L2: it runs while the request row is
still allocated, and a failing `after_release` there would leave the row
allocated and `mark_kv_released` unrun, where the fork has already freed
both.

Note on D without an upstream change: the plugin's cache could capture and
then drain inside its `checkpoint` override when `req.finished()` (the
release-time call), and drain in `on_release` for releases without a
checkpoint (this concerns D only; L2 stays the `after` hook above). The drain is host-blocking and no allocation can run on the
scheduler thread between `free_kv_row` and `on_release`, so no page is
reused before the drain completes (invariant 3 holds for reuse). It
breaks invariant 5: a failed drain raises after the pages were given back.
It also relies on `req.finished()` to tell the release checkpoint from a
chunk checkpoint. Not recommended unless gap 1 is refused upstream.

## 4. Upstream asks to file after #42923 and #43023 land

Both are small, keep upstream's naming style, and have default no-op
implementations on `BasePrefixCache`.

1. **Pre-free point in `release_kv_cache`.** One call after the final
   `checkpoint` and before the first `free_kv_row`, for every release
   (checkpointed or not), e.g. `tree_cache.before_free_kv_row(req)`
   ("asynchronous readers of the row's KV must finish before the row is
   given back"). Removes the D part of M03 (and hosts the C4 check). With
   a `checkpoint` override for C2 and the plugin `after` hook on
   `release_kv_cache` for L2, M03 needs no REPLACE.
2. **Cache-driven prefill chunk cap.** A `BasePrefixCache` method returning
   an optional token cap for a request's next chunk, consulted by
   `PrefillAdder.add_one_req` and `add_chunked_req` (so a checkpoint lands
   on a page boundary before the logits tail), and the `ignore_eos` fast
   path skipped when the request needs a host load-back. Removes P01 and
   the cap part of P02. The charge part of P02 is covered by mapping (b);
   with mapping (a) the same PR would need a pending-prefix charge.

Not asked: an after-row-free hook (L2 stays a plugin `after` hook on
`release_kv_cache`; an upstream hook would only rename that point), a
free-group listener (M02 and F stay a narrow `after` hook), a
weight-update cache hook (B06 stays a `before` hook), an allocation
rollback API (R4 stays an `around` hook), a generic name for
`maybe_hand_to_session` (optional cosmetic follow-up; the position is
right), and KV-pool runtime attachment (Q03/R01 stay `after` hooks).

## 7. Draft PR description (for ask 1 + ask 2, not ready to open)

Title: `[MemCache] Let a cache drain before its rows are freed and cap prefill chunks at its checkpoints`

Summary: Caches that keep request state outside the tree (host prefix
snapshots, asynchronous device-to-host copies) need two points the
lifecycle does not offer: a point after the final `checkpoint` and before
`free_kv_row` where asynchronous readers of the row finish, and a way to end
a prefill chunk on a checkpoint boundary so the state there can be captured
before the logits tail runs. Adds `BasePrefixCache.before_free_kv_row(req)`
(no-op) called by `release_kv_cache`, and an optional chunk cap consulted
by `PrefillAdder`; the `ignore_eos` fast path no longer bypasses a pending
host load-back. No behavior change for in-tree caches.

Test plan: CPU unit tests under `test/registered/unit/mem_cache/` (call
order of `checkpoint`, `before_free_kv_row`, `free_kv_row`, `on_release`
for checkpointed and non-checkpointed releases, with a recording cache) and
`test/registered/unit/managers/test_prefill_adder.py` (cap applied to new
and continuing chunks; `ignore_eos` request with a pending load-back takes
the regular path). Evidence of an out-of-tree user: the plugin's Phase 4
backend and its lifecycle ledger test.
